## Session 7: The Real Reveal — BeemSpec & BeemFlow Runtime

### BeemFlow Runtime (Archived):
- **What it was:** "GitHub Actions for every business process" — a workflow protocol, runtime, and global tool registry for the age of LLM co-workers
- **Tech:** Written in Rust, worked well
- **Features:** Define workflows in YAML/JSON/native code, execute via CLI/HTTP/MCP, instant access to thousands of curated MCP servers and LLM tools, natural language workflow generation
- **Status:** Archived on GitHub. Concepts still apply. Using n8n for automation instead.
- **Vision (from README):** Positioned around the $15T generational wealth transfer — 52% of U.S. businesses owned by 55+ nearing retirement. BeemFlow was meant to be the automation infrastructure that enables individuals to learn, optimize, and acquire small businesses. Strongly worded manifesto against technocratic consolidation and in favor of individual ownership.
- **Compared against:** Zapier/Make.com (GUI-based, break at scale), n8n/Temporal (complex infrastructure), Power Automate (vendor lock-in)

### BeemSpec (Active — In Use):
- **What it is:** The planning layer for AI-native software teams. Story mapping and release planning tool that doubles as an AI build orchestrator.
- **The problem it solves:** Product teams spend significant effort translating plans into work that AI coding agents can act on. Requirements live in one tool, tasks in another, context is lost at every handoff. AI agents need structured, complete context to produce good output.
- **How it works:**
  - Plan visually with story maps (columns = user activities/tasks, rows = releases)
  - Each story captures requirements, acceptance criteria, design links, edge cases, technical guidelines in structured fields consumable by both humans and AI agents
  - Click "Build Release" → BeemSpec creates an AI coding session (powered by OpenCode), seeds it with full story context, instructs the agent to implement
  - Track build progress per story, retry failures, link back to AI session
- **Integrations:**
  - **Linear:** Bidirectional sync. Stories in BeemSpec auto-appear as Linear issues. Changes flow both ways.
  - **OpenCode:** Session creation, context seeding, MCP server for agent-to-app communication
  - **MCP Server:** Exposes tools for AI agents to load story context and report blockers during implementation
- **Three-system architecture:**
  - BeemSpec = Planning source of truth (what to build and why)
  - Linear = Execution coordination (when and who)
  - OpenCode = AI implementation runtime (how — the code)
- **Key capabilities:** Story map management, structured story specs, build runs, Linear integration, OpenCode integration, team collaboration, MCP server
- **Status:** Alec is actively using it as a replacement for StoriesOnBoard, coordinating his own coding agents. The project's goal is to codify his product management and agentic coding workflows into a single coordination layer. Story maps are the main interface.
